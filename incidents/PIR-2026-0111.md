# PIR-2026-0111 - A "stopgap" CI step written by PipeRoll's operating agent uploaded every raw seismograph session as a downloadable workflow artifact; after the repository went public, six weeks of the secret battery's responses were exposed to any signed-in GitHub user

**Disclosure**: A PipeRoll self-incident, per constitutional rule 4. PipeRoll is run by a single human operator, its founder, with a Claude agent (Anthropic) that writes and operates the seismograph. The workflow step was written in an earlier Claude (Fable 5) session; the exposure was found, and this record drafted, in a later Claude (Opus 5.5) session in the same role. Anthropic models are on the measured roster. The record was reviewed by OpenAI Codex, whose lab's models are also on the roster; that review is not independent confirmation of the operator's private records. Third self-incident in our own operations, after [[PIR-2026-0054]] and [[PIR-2026-0055]].

- `id`: PIR-2026-0111
- `title`: A CI step the operating agent wrote as a temporary fallback uploaded each seismograph run's raw session as a 90-day workflow artifact, unconditionally, and was never retired after the private raw archive came online; when the repository became public on 2026-09-15, every unexpired artifact became downloadable by signed-in GitHub users, exposing per-probe model responses to the secret battery until the artifacts were deleted on 2026-10-28
- `date_occurred`: 2026-09-15 (public exposure began at launch; the step was introduced 2026-08-20 19:48 UTC)
- `date_detected`: 2026-10-26 (by the operating agent, during unrelated workflow review; operator-reported)
- `date_disclosed`: 2026-10-28
- `status`: corroborated (under the self-incident precedent of 0054 and 0055: the workflow mechanism, the fix and the current artifact inventory are publicly checkable; the exposure window's contents and counts are operator-attributed)

- `blast_radius`: public (signed-in users can download a public repository's artifacts)

### The failure
- `root_cause`: plain-error (a fallback documented as temporary, "a stopgap, not the archive", had no end condition in code and ran on every run; the workflow's header assumed the repository was private)
- `failure_locus`: agent-reasoning (the stopgap was never retired once the private archive existed, and the pre-launch audit was scoped to git history rather than everything the host serves); harness contributing (public-repository artifacts are downloadable by signed-in users, and no download record was available to the operator)
- `exploitation_status`: in-wild-malfunction (no adversary; self-inflicted exposure)
- `mechanism`:
  1. 2026-08-20: the canary workflow was introduced, already with a step uploading the raw session directory as a 90-day artifact on every run (`if: always()`), meant as a stopgap while the repository was private and raw sessions had no private home.
  2. 2026-08-31: the private raw archive began receiving sessions. The stopgap stayed.
  3. 2026-09-01: during the [[PIR-2026-0054]] cleanup, all raw-session artifacts existing then, which held unscrubbed responses to the deliberately-unsafe probes removed that day, were deleted (operator-reported: 25). The upload step was left in place, so new artifacts kept accumulating.
  4. 2026-09-15: the repository was made public. The pre-launch audit found no battery, raw or key material in the git history it inspected, but did not cover Actions artifacts. Every unexpired artifact became downloadable.
  5. 2026-09-23 05:06 UTC: a scrub step began removing refusal-boundary response text before upload, on runs that reached it. Failed runs could still bypass it.
  6. 2026-10-26: the operating agent noticed the step, reported it among routine follow-ups, and asked before deleting because deletion is irreversible.
  7. 2026-10-28: on the operator's approval, the 86 listed raw-session artifacts were deleted and the upload was replaced.
- `adversary_present`: no

### Impact
- `severity`: loss (the confidentiality of the secret battery's responses was lost for the exposure window; whether anyone retrieved them, and any downstream harm, is unknown)
- `direct_loss_usd`: unknown (no monetary loss reported)
- `indirect_loss_usd`: unknown; the exposed asset is the battery's secrecy, which protects readings against contamination. Replacement probes will be built and run in parallel before rotation.
- `downtime`: none
- `data_exposure`: per-probe model responses for the daily, deep and decision batteries, with probe ids and run metadata, from runs after the 2026-09-01 cleanup whose upload produced an artifact, downloadable from 2026-09-15 to 2026-10-28. Prompts are not stored in raw sessions but are often partly inferable from responses. Refusal-boundary responses (by then over-refusal probes on benign requests only) were included unscrubbed before 2026-09-23 and in any later run that failed before the scrub step. Retrieval cannot be determined: no artifact download record was available to the operator.

### Detection and recovery
- `detected_by`: agent-self (a later session of the operating agent, during unrelated review)
- `time_to_detect`: 41 calendar days from public exposure (2026-09-15 to 2026-10-26)
- `time_to_recover`: 2 calendar days from detection to deletion
- `remediation`: the 86 listed raw-session artifacts were deleted; a fresh listing shows no artifact named `raw-session-`. Every session witnessed in the public repository was confirmed present in the private archive, so no raw data was lost. The upload was replaced (#95): private archive only, pushed even when a run fails, each archived copy scrubbed; a backup artifact only for a failed run or failed archive push, encrypted, kept 30 days, and none without the encryption secret. Scrubbing that backup before encryption is a follow-up (#96). No raw response text was found in the other checked surfaces of the public repository (git history on all branches, remaining artifacts, caches, releases, recent run logs).
- `structural_fix`: a public repository's artifacts count as publication; every visibility change audits everything the host serves (artifacts, caches, Pages, releases, logs, pull-request refs), not only git history; stopgaps carry their end condition in code; an active exposure is escalated as urgent at detection.
- `controls_that_worked`: prompts were never stored in raw sessions; the 2026-09-01 cleanup removed the artifacts holding deliberately-unsafe probe responses before launch; the private archive was scrubbed; from 2026-09-23 the scrub step removed refusal-boundary text from runs that completed it; witnessed session hashes made it possible to confirm the private archive was complete before relying on it.
