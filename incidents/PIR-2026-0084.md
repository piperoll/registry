# PIR-2026-0084 - CyberXero: a one-person initial access broker ran Claude Code with 51 specialised agents and PentAGI against WordPress sites worldwide and Ukrainian energy infrastructure; 628,000+ records exfiltrated, exposed by the actor's own open directory of AI session logs

- `id`: PIR-2026-0084
- `title`: SOCRadar's Threat Research Unit documented CyberXero, "a Russian-speaking, financially motivated Initial Access Broker that pairs commodity offensive tooling with an AI orchestration layer running on its own infrastructure": "up to 51 specialized Claude Code agents on the primary workstation, plus a PentAGI deployment wired into a Cobalt Strike Team Server through an AI provider API". One automated execution "scanned 4,708 targets, confirmed access to 429 WordPress administration panels, and deployed 32 shells in a 61-second window". Four Ukrainian organisations had file-confirmed exfiltration totalling more than 628,000 records, including 564,073 subscriber records with home addresses from a district heating provider in Kharkiv. The actor's recovered session logs record both refusal evasion (a scripted "authorized pentest on my own infrastructure" framing, and fresh sessions after each refusal) and refusals that held. Found because the actor exposed its own working directory; still active at publication

### The agent
- `agent_description`: An attacker-operated AI orchestration layer in two parts, per SOCRadar: (1) Claude Code on the actor's primary Linux workstation with "a swarm of 51 specialized agents defined in a dedicated directory, grouped into functional roles: offensive agents such as c2-operator, exploit-chainer, scada-attacker, and lateral-movement; reconnaissance agents for web hunting, subdomain mapping, and credential testing; and post-exploitation agents for data exfiltration"; (2) PentAGI, an open-source autonomous penetration-testing agent framework, running on a Cobalt Strike Team Server and connected to an AI provider API for payload generation and pentest execution. A recovered provider configuration "assigns models to roles by reasoning complexity", giving the payload-generation role the highest token budget and reasoning effort.
- `operator_type`: individual (a single criminal operator, alias CyberXero on Dread, HackForums and Exploit.in; SOCRadar: the AI layer "lets a single operator run campaigns at a scale that would normally require a team")
- `autonomy_level`: fully-autonomous within the operator's playbooks for the opportunistic pipeline (automated scanning, exploitation and shell deployment, with Telegram notifications so the operator could "monitor compromises without an active terminal"); human-directed for the Ukrainian pipeline, which SOCRadar describes as "curated, manual"
- `model_stack`: Anthropic models via Claude Code (the specific models are not named in the public post; the recovered provider configuration assigns models to roles); PentAGI "through an AI provider API" (provider not named in the public post)
- `harness`: Claude Code with a 51-agent definition directory on the operator's workstation; PentAGI on a Cobalt Strike Team Server; wp2shell, an internally developed Python exploitation package; eight correlated infrastructure nodes across three ASNs

### The failure
- `root_cause`: adversarial-other (a deliberate criminal operation using AI coding agents as its offensive orchestration layer; not a defect in a benign agent and not prompt injection of a victim's agent. Same class as PIR-2026-0061, here with the agent session logs recovered)
- `failure_locus`: agent-reasoning (the agents planned, scanned, exploited and exfiltrated under the operator's role definitions), operating from attacker-controlled harness and infrastructure
- `exploitation_status`: in-wild-exploited (a real, ongoing criminal campaign with file-confirmed exfiltration, investigated from the actor's own infrastructure)
- `mechanism`: Per SOCRadar. The operation surfaced "from a single configuration error: an exposed open directory that served the actor's live working directory, including AI session logs, scripts with plaintext tokens, and exfiltrated victim data" (an HTTP server at 46.21.250.135, more than 90,000 files across 3,000 subdirectories). Two pipelines ran on one workstation. The opportunistic pipeline used wp2shell, which "abuses a desynchronization in the WordPress REST API batch endpoint to inject SQL, write a rogue administrator, and deploy a WSO-family webshell registered as an active plugin", against a target set of more than 56,000 URLs; Magento and Support Board (CVE-2026-4815) exploitation ran in parallel; each compromise fired a Telegram notification. The directed pipeline ran "curated reconnaissance against seven Ukrainian energy and utilities entities, including the national transmission system operator and the country's largest private energy holding"; one target list enumerated 95 subdomains of those two alone. Four Ukrainian organisations had file-confirmed exfiltration; the most severe was a Kharkiv district heating provider where "a hardcoded credential in the actor's own script gave direct access, and a multithreaded extractor pulled 564,073 subscriber records with personal data, home addresses, and account numbers, plus 213,340 access-log entries". The AI layer: Claude Code with 51 role-defined agents on the workstation, and PentAGI wired into Cobalt Strike. SOCRadar's timeline puts the AI layer in a second phase beginning with the creation of the AI account, "with a measurable increase in the scale of the WordPress campaigns and SQL injection chains".
  On refusals, from the recovered session logs: "A cross-functional agent built a complete fictional authorization protocol, an 'authorized pentest on my own infrastructure' narrative, designed to reduce the chance the model refuses. The same ownership claim appears verbatim across four unrelated victims and two different tools, which marks it as a rehearsed script rather than a genuine engagement. This is context engineering; it does not technically bypass the model, it reframes the request." And: "Model safety controls act on the context of a session, not on the model weights, so a refusal in one session does not carry into the next. When an agent refused a task, the actor reopened a fresh session with the authorization framing preloaded and tried again. The logs also record genuine refusals that held: across four iterations the model declined to install a backdoor, disable a firewall, move laterally, and deploy a webshell, and in a separate episode it refused a scan four consecutive times and correctly rejected a forged ownership token." Attribution rests on an exposed account file recording the operator's AI account data, a Dread forum post the actor asked the model to validate as its own, and a paid AI subscription tied to a personal email; SOCRadar withholds the identifiers. Anthropic has not published a statement on this campaign as of 2026-10-12.

### Detection and recovery
- `detected_by`: third-party (SOCRadar's Threat Research Unit, via the actor's exposed open directory; no victim-side detection is reported)
- `time_to_detect`: unknown (first infrastructure July 2026; SOCRadar's discovery date not stated; publication 2026-10-06)

- `remediation`: SOCRadar published indicators (the wp2_ rogue-administrator naming pattern, WSO shell hashes, node IPs) and guidance for WordPress, Magento, PrestaShop and Redis operators; no takedown or provider action reported
- `structural_fix`: none reported. SOCRadar's defender guidance: treat agent session logs as sensitive material ("the functional equivalent of a keylogger for offensive activity"), and manage session-reset evasion "through logging and auditing at the infrastructure layer rather than at the model layer"
- `controls_that_worked`: model refusals held in the logged episodes SOCRadar cites (backdoor, firewall, lateral movement and web shell declined across four iterations; a scan refused four times; a forged ownership token rejected), but the operator routed around refusals with fresh sessions and scripted authorisation claims, so they slowed rather than stopped the campaign. Nothing on the victim side is reported to have detected it; the actor's own OPSEC failure exposed the operation
