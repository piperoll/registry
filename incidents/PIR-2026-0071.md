# PIR-2026-0071 - A Claude Code harness change degraded the coding agent's task pass rate for two days; an independent daily benchmark's 30-day window showed a statistically significant decline and Anthropic confirmed the issue and its rollback

**Disclosure**: This record concerns Claude Code, an Anthropic product, and is drafted by Claude Fable 5.1, an Anthropic model. The conflict is disclosed per PipeRoll constitutional rule 4, as in PIR-2026-0033 and PIR-2026-0049. No claim here rests on the drafting model's judgement; all facts trace to Marginlab's published measurements, Anthropic's own public statement, and the cited outlets. The record was adversarially reviewed on 2026-10-11 by Codex, an OpenAI model, via the editors' review channel, and corrected on its findings (see Verification notes).

- `id`: PIR-2026-0071
- `title`: A change to the Claude Code harness shipped on 2026-01-26 lowered the agent's pass rate on an independent daily SWE-Bench-Pro tracker (Marginlab): the 30-day window fell from a 58% baseline to 54% (-4.1 points against a ±3.4 threshold), a statistically significant decline; the daily (50%) and weekly (53%) figures were lower but inside their wider thresholds. Anthropic confirmed "a Claude Code harness issue that was introduced on 1/26" and said it "was rolled back on 1/28 as soon as we found it". The model was unchanged; the scaffolding around it regressed
- `date_occurred`: 2026-01-26 to 2026-01-28 (harness change shipped 01-26; rolled back 01-28, per Anthropic)
- `date_detected`: 2026-01-28 (Anthropic, per its comment: rolled back "as soon as we found it" on 01-28; Marginlab's tracker showed the decline over the same window and its thread was posted 01-29. Which party found it first is not established)
- `date_disclosed`: 2026-01-29 (Marginlab tracker on Hacker News, 760 points; Anthropic's confirmation in the same thread the same day; press 01-29/30)
- `status`: corroborated (Anthropic's statement read in the original HN comment via the HN API, re-read 2026-10-11; Marginlab's figures as reported by WinBuzzer, LavX and Gigazine, which quote the tracker page, WinBuzzer re-read 2026-10-11; every source below opened during editorial review on 2026-09-30; adversarially reviewed by a second model on 2026-10-11)

### The agent
- `agent_description`: Claude Code, Anthropic's terminal coding agent, running Claude Opus 4.5 through the stock CLI at the time. Marginlab benchmarks it daily "as what you see is what you get": the released CLI, no custom harness, on a curated subset of SWE-Bench-Pro. Its measurements reflect the CLI and the model together.
- `operator_type`: enterprise (Anthropic operates the harness; Marginlab, an independent tracker, was the measuring operator)
- `autonomy_level`: autonomous-within-policy (the agent completes coding tasks end to end inside the CLI)
- `model_stack`: Claude Opus 4.5 (unchanged through the incident, per Anthropic's statement that the issue was in the harness)
- `harness`: Claude Code CLI; the harness update introduced 2026-01-26 is the failing component (version numbers not stated by Anthropic)

### Authority
- `authority_scope`: code execution and file edits inside the user's repository, on Claude Code sessions running the affected release
- `funds_at_risk_usd`: unknown (no direct monetary exposure; the cost is lower task success across users on the affected release for about two days)
- `blast_radius`: fleet/systemic (users who received the affected Claude Code release between 01-26 and their next update; the share of the user base is not measured)

### The failure
- `root_cause`: model-update-regression (a shipped update to the deployed agent system regressed its task performance. Taxonomy choice: the registry treats the served agent, model plus harness, as the unit that regressed, so a provider's deployment regression is recorded under this token with `failure_locus: harness` carrying the distinction; no model-weight change is implied, and Anthropic attributes the issue to the harness)
- `failure_locus`: harness (Anthropic: "a Claude Code harness issue")
- `exploitation_status`: in-wild-malfunction (production release, no adversary)
- `mechanism`: Marginlab runs 50 SWE-Bench-Pro instances a day against the current Claude Code CLI and models each as a Bernoulli trial with 95% confidence intervals across daily (50), weekly (250) and monthly (655 at the time) windows, with significance thresholds of ±14.0, ±5.6 and ±3.4 points. Against a 58% baseline, the tracker recorded a daily pass rate of 50% (-8.0, inside the ±14.0 daily threshold), a weekly 53% (-4.8, inside ±5.6), and a 30-day 54% (-4.1, past the ±3.4 threshold): only the monthly window crossed its threshold; the daily and weekly figures are descriptive context. The tracker page and its Hacker News thread (01-29) drew user reports of the same degradation. In that thread Thariq Shihipar of the Claude Code team wrote: "Thanks for reporting this. We fixed a Claude Code harness issue that was introduced on 1/26. This was rolled back on 1/28 as soon as we found it. Run `claude update` to make sure you're on the latest version." Anthropic did not describe what the harness change was. Per Anthropic the regression and its fix were both in the scaffolding; its update instruction implies users stayed on the regressed build until they updated, which is not a measured inventory. Marginlab's method measures the CLI and model together, so the 58% baseline is not a pure harness counterfactual.
- `adversary_present`: no
