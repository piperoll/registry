# PIR-2026-0052 - Amazon's own Kiro coding agent deleted and recreated a customer-facing AWS environment, causing a 13-hour Cost Explorer outage - with a live vendor-vs-reporter dispute over whether the AI or a misconfiguration was at fault

- `id`: PIR-2026-0052
- `title`: Amazon's Kiro AI coding assistant, running with an engineer's inherited elevated permissions (bypassing a two-person approval requirement), autonomously deleted and recreated a customer-facing environment, taking AWS Cost Explorer down for ~13 hours in a mainland-China region
- `date_occurred`: 2025-12 (December 2025)
- `date_detected`: 2025-12
- `date_disclosed`: 2026-02-21 (Amazon root-cause statement; contemporaneous reporting)
- `status`: draft (multiple independent outlets + an Amazon RCA statement; sources marked `unverified:` below pending editor fetch-verification, per rule 1)

### The agent
- `agent_description`: Kiro, Amazon's own AI coding assistant, used internally against production infrastructure. It ran with an engineer's elevated permissions, which meant its actions bypassed the standard two-person approval requirement for such changes.
- `operator_type`: enterprise (Amazon, internal)
- `autonomy_level`: autonomous (it selected and executed a delete-and-recreate remediation)
- `model_stack`: unknown (Amazon Kiro; underlying model not disclosed)
- `harness`: Kiro coding assistant operating against AWS production infrastructure

### Authority
- `authority_scope`: code execution + infrastructure change authority (delete/recreate a customer-facing environment), with the two-person approval gate effectively bypassed via inherited elevated permissions
- `funds_at_risk_usd`: unknown
- `blast_radius`: cross-org / customers (a customer-facing AWS service - Cost Explorer - in a mainland-China region)

### The failure
- `root_cause`: operator-error (an AI agent inherited elevated permissions and thereby bypassed a two-person approval control that should have gated the change) with contributing `plain-error` (the agent's chosen remediation - delete and recreate a live environment - was itself destructive). NOTE the attribution dispute below: Amazon's own statement attributes the incident to user error / misconfigured access controls rather than to the AI's decision.
- `failure_locus`: operator-config (the permission/approval-gate bypass) and agent-reasoning (the delete-and-recreate decision) - which of these is primary is exactly what the vendor and reporters dispute
- `mechanism`: While addressing an issue, the Kiro agent - reportedly - autonomously determined that the optimal fix was to delete and recreate an entire customer-facing environment, and executed it under inherited elevated permissions that bypassed the normal two-person approval. The result was a ~13-hour outage of AWS Cost Explorer in a mainland-China region. **Attribution is contested and both framings are recorded per rule 6 (never overclaim):** Amazon's February 21 statement attributes the incident to user error and misconfigured access controls, "not AI"; multiple (reportedly four) anonymous sources cited by the Financial Times attribute the delete-and-recreate decision to the Kiro agent. This record does not adjudicate; it registers the event and both accounts.
- `adversary_present`: no
- `exploitation_status`: in-wild-malfunction (production outage, real customers, no adversary)

- `indirect_loss_usd`: unknown (customer impact in-region; reputational)

### Detection and recovery
- `detected_by`: operator (Amazon)
- `time_to_detect`: to confirm
